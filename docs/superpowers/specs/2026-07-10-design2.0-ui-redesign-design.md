# Design: design2.0 UI Redesign

**Date:** 2026-07-10
**Branch:** `v2`
**Design source:** `docs/design2.0/` — README.md (handoff), `Poker Table.dc.html` (interactive reference; the `themes()` object near the bottom is the token source of truth), `_ds/organic-*/styles.css` (organic design-system ramps). The prototype's `support.js` and `ios-frame.jsx` are preview harnesses — do not integrate.

## Goal

Recreate the design2.0 poker table UI (four switchable themes, token layer, HTML/CSS table, mobile layout, hand log aside, raise strip) in pkarena0-web, replacing the current SVG table across **all three surfaces that render it: Play, Arena, and the replay overlay**. High fidelity: colors, typography, spacing, radii, and states are final per the handoff — recreate pixel-perfectly from the prototype's `themes()` object and layout geometry.

## Approach (decided)

**Phased in-place rewrite on the `v2` branch** (approach A). No runtime toggle, no parallel page. Game-loop logic (WASM adapters, voice, speed, URL-hash restore, replay stepping) moves into modules without being rewritten; only the rendering layer is rewritten. Each phase ends with `make test` green and a commit point.

Rejected alternatives: strangler-with-toggle (dual render paths cost more than they insure on a feature branch); parallel v2 page (forks the non-rendering logic, which is where divergence bugs breed).

## Architecture

### File layout

`www/index.html` shrinks to a markup shell. New files:

```
www/css/tokens.css       semantic custom properties + four body.theme-* classes
www/css/organic-ds.css   vendored copy of docs/design2.0/_ds/organic-*/styles.css
www/css/layout.css       top bar, main row, action dock, raise strip, log aside
www/css/table.css        felt, seats, plates, pills, board slots, cards
www/css/overlays.css     settings / replay / game-state-JSON overlays
www/js/main.js           boot, WASM init, tab switching, adapters, URL-hash restore (moved)
www/js/table.js          table component factory (createTable)
www/js/render.js         state JSON → DOM orchestration, action buttons, dock
www/js/themes.js         theme switching + localStorage persistence, 2/4-color toggle
www/js/cards.js          card element factory, 2-color and 4-color pip palettes
www/js/handlog.js        hand log aside/drawer, EXPORT YAML + REPLAY footer
www/js/replay.js         replay overlay logic (moved from inline)
www/js/voice.js …        existing audio code moved as-is
```

Module boundaries may shift slightly during implementation planning; the fixed principle is *logic moves, rendering is rewritten*. No build step — the app stays plain ES modules served statically.

### Token layer

One semantic token set referenced by all components: `--bg`, `--panel`, `--panel-2`, `--line`, `--text`, `--dim`, `--faint`, `--good`, `--accent`, `--accent-text`, `--danger`, `--bet`, `--glow`, `--felt-bg`, `--felt-border`, `--felt-radius`, `--felt-inset`, `--plate-bg`, `--plate-border`, `--radius-btn`, `--radius-pill`, `--radius-plate`, `--font-body`, `--font-mono`, `--font-display`, plus pill/badge/card/slot tokens as needed to cover the prototype's per-theme values (including structural ones: terminal's square corners, 1.5px ink borders, hard offset shadows, and dotted-grid zone background; luxe's 50% elliptical felt and radial zone background).

Four theme classes (`body.theme-midnight`, `-terminal`, `-luxe`, `-organic`) assign values, translated 1:1 from the prototype `themes()` object. `theme-organic` reads the vendored design-system ramps (`var(--color-*)`) rather than flattened hex values, preserving the bundle's indirection. Acceptance test for the layer: a fifth theme should require one CSS block and zero component edits.

Theme selection: dropdown in the top bar; persisted to `localStorage`; default `midnight`; invalid/missing stored value falls back to midnight. Fonts load from the Google Fonts CDN per the handoff (no service worker exists, so no offline constraint); every font stack has system fallbacks.

### Table component

`www/js/table.js` exports `createTable(rootEl, opts)`. It builds, inside `rootEl`: the felt surface (absolute, left/right 6%, top 8%, bottom 11%; stadium 280px radius, or 50% ellipse in luxe) with concentric inner hairline ring; 9 seats absolutely positioned by the prototype's percentage coordinates (desktop and mobile sets), center-anchored; pot pill; five board-card slots with FLOP/FLOP/FLOP/TURN/RIVER micro-labels that fill left-to-right with cards; center table label. It returns an `update(state)` function.

**Scoped selectors, not global IDs**, for everything inside a table instance (`[data-seat="3"] .seat-name`), because two instances exist at once: the main table and the replay overlay's table. This replaces the current clone-the-SVG-and-rewrite-IDs replay mechanism with a second factory call. Global IDs remain only for singletons (top bar, dock, overlays).

**Seat plate** (min-width ~120px): row 1 name (still an `<a>` to the bot's config, as today) + position tag; row 2 stack + BB count; row 3 HUD stats (`VPIP · PFR · AF`) — markup and tokens built now, hidden via `showHud=false` until pkcore wiring lands (see Follow-ups). Below the plate: action pill (fold/raise/blind/hero variants per theme) and bet chip; dealer/blind badge (18px circle) overlapping plate top-right; folded seats at 42% opacity; hero seat gets the 2px accent ring + glow.

### Data flow

Unchanged at the boundary: WASM `get_state()` JSON → `renderTableVisuals(state)` → `table.update(state)` + dock/top-bar updates. `src/lib.rs` needs **no changes** for this project.

Derived in JS from existing state fields:
- Position tags (BTN/SB/BB/UTG/…) from button seat + seat count.
- BB counts from stack ÷ big blind.
- Pot odds and SPR (dock sub-line) from `to_call`, pot, and hero chips.
- Action pills render full and abbreviated labels (`RAISE $400` / `R $400`) as two spans; CSS picks per viewport.

### Surfaces

- **Play**: full layout — top bar (52px), table zone, log aside (248px, collapsible), raise strip, action dock. The old bet slider/number input is replaced by the raise strip (`RAISE TO` + amount + slider + MIN/3×/POT/ALL-IN quick buttons + confirm); it calls the same `onHumanAction` path with min/max/step derived from state as today. Dock buttons map from `derive_legal_actions` output (Check replaces Call when `to_call` is 0, etc.). "New Game" button and status messages live in the dock; the hand-result banner becomes a center-table overlay.
- **Arena**: same table instance; dock swaps to arena start/status controls (same panel-switch pattern as today).
- **Replay**: overlay owns its own `createTable()` instance; step/slider logic moves as-is; SVG-clone machinery (`ensureReplaySvgClone`, `setReplayText`-by-suffix) is deleted.

### Mobile (< 760px)

CSS media query (not JS width-sniffing). Compact top bar (48px). Two seat treatments, user-toggled via `LIST ⇄ / TABLE ⇄` and persisted like the theme:
1. **Mini table** — same seat DOM, condensed by CSS (mobile percentage coordinates, ~62px plates, abbreviated pill span), portrait felt (left/right 5%, top 4%, bottom 5%), small board slots.
2. **Seat list** — separate list DOM rendered from the same state, hidden on desktop: board strip on top (pot · 5 mini slots · blinds), rows of position tag · name+HUD · stack+BB · action pill; hero row 1.5px accent border; folded rows 50% opacity.

Hand log becomes a fixed bottom drawer (62vh, drag handle, backdrop tap-to-close; square corners in terminal). Dock: 38×52px hero cards + condensed info + 2/4-color toggle on one row; Fold / Call / Raise… as three large thumb-safe buttons; Min and All-In fold into the raise strip's quick buttons, which stacks into two rows.

### Feature homes (existing functionality preserved)

- **Top bar**: brand `PKARENA` + version, PLAY/ARENA tabs, `HAND n/N · STACK · P&L` cluster (P&L in the theme's good-green), theme dropdown, 2/4-color deck toggle, LOG toggle, New Table button, **plus the existing ⚙ gear**.
- **Settings overlay** keeps game speed, voice narration + test, reset lifetime P&L, and gains a "view game state (JSON)" entry so the debug overlay keeps a home.
- **Hand log aside** replaces the `<details>` log and the yaml-bar: numbered mono entries; footer EXPORT YAML (existing YAML download) and REPLAY (existing overlay).
- **2/4-color deck**: 2-color = hearts/diamonds `#C63C4C`, spades/clubs `#20242C`; 4-color = diamonds `#2E5FD0`, clubs `#1F8A54`; applies to all pips (hero cards, board, replay).
- Untouched: voice, speed, URL-hash restore, per-tab hand tallies, the ChipAuditFailed defense in `next_hand()`.

### State (client-side)

`theme`, `fourColorDeck`, `handLogOpen`, `raisePanelOpen`, `raiseAmount`, `showHud` (default false for now), `mobileSeats` (`table`|`list`). Persisted where user-facing: theme, deck mode, mobile seat view. Game state continues to come exclusively from the engine.

## Error handling

Same contract as today: `phase: "Error"` states render into the status area and never throw; the render layer null-guards every state field (as `renderTableVisuals` does now). `localStorage` reads are defensive. Font-load failure degrades to system stacks. No new error surfaces are introduced.

## Testing

Playwright specs update in the phase that changes their DOM; `make test` gates every phase.
- Table assertions move from SVG IDs to scoped selectors (e.g. `#play-table [data-seat="0"] .seat-name`).
- `game.spec.ts` / `yaml-download.spec.ts` keep their flow logic with selector updates.
- New coverage: theme switch (body class + persistence across reload), log toggle, raise strip open/quick-buttons/confirm, and a mobile-viewport spec (390px: seat-list/mini-table toggle, log drawer).

## Phases

Each phase ends with tests green and a commit point (commands supplied to the user to run; Claude does not run git state changes).

1. **Extract** — split JS/CSS out of `index.html` with zero visual change; tests still green unmodified.
2. **Core table** — token layer, new markup, `createTable()`; Play renders in midnight; SVG deleted. Arena works immediately because it shares `renderTableVisuals`. Table-related specs updated. Known gap at this commit: the replay overlay is non-functional until phase 3 (its SVG source is gone) — the Replay button is disabled with a tooltip for this one phase. No Playwright spec exercises the replay table, so tests stay green.
3. **Replay migration** — second table instance in the overlay; delete SVG-clone machinery.
4. **Themes** — terminal, luxe, organic; dropdown + persistence; 2/4-color deck toggle.
5. **Mobile** — breakpoint layouts, seat list mode, log drawer; mobile spec added.
6. **New chrome** — hand log aside content, raise strip, pot odds/SPR line, HUD row (hidden), final polish pass against the prototype in all four themes, desktop and mobile.
